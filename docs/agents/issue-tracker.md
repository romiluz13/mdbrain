# Issue tracker: GitHub

Issues and specs for this repository live as GitHub issues in
`romiluz13/mdbrain`.

## Conventions

- Create, read, comment on, label, and close issues through GitHub.
- Infer the repository from the configured `origin` remote.
- Every issue or comment generated during triage must begin with:
  `> *This was generated by AI during triage.*`
- Pull requests are not a triage request surface.

## Skill operations

- When a skill says to publish to the issue tracker, create a GitHub issue.
- When a skill says to fetch a ticket, read the full issue, comments, and
  labels.
- Use native GitHub issue dependencies for blocking relationships when
  available. Otherwise, add a `Blocked by: #...` line to the issue body.
- An issue is unblocked only when all issues it depends on are closed.
- Claim an issue by assigning it before implementation.

## Wayfinding

A wayfinder map is one issue with linked child issues. Decision tickets should
use native sub-issues and dependencies when available, with task-list and
`Blocked by:` fallbacks otherwise.
