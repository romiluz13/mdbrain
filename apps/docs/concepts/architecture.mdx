MDBrain owns the governed company wiki. Memongo owns long-term memory. MDBrain
uses Memongo exclusively through a pinned, versioned HTTP contract and never
imports Memongo storage internals.

## Packages

| Package | Role |
|---------|------|
| `@mdbrain/wiki-engine` | Governed wiki schema, CRUD, search, revisions, OKF, and connectors |
| `@mdbrain/memory-bridge` | Compatibility-checked Memongo HTTP gateway |
| `@mdbrain/memory` | Aggregate client and gateway exports |
| `@mdbrain/client` | TypeScript HTTP client SDK |
| `@mdbrain/tools` | AI SDK tool helpers for supported operations |
| `@mdbrain/lib` | Shared types and utilities |

## Runtime flow

```text
Client SDK / HTTP -> apps/api -> memory-bridge -> Memongo HTTP -> Memongo storage
                              \-> WikiStore -> wiki MongoDB
                              \-> delivery intents -> receipt-gated promotion

MCP client (stdio) -> apps/mcp -> client SDK -> apps/api
```

The wiki MongoDB contains only MDBrain-owned collections. Production requires
transactions. Event-producing memory writes first persist a durable local
intent, then dispatch to Memongo with a caller-owned idempotency key. Explicit
wiki promotion runs only after a Memongo receipt is persisted. A bounded
background reconciler resumes stale, retryable, ambiguous, and
promotion-pending intents with the original key.

## Apps

| App | Port | Description |
|-----|------|-------------|
| `apps/api` | 3847 | Hono HTTP API and orchestration gateway |
| `apps/mcp` | stdio | MCP server wrapping the HTTP API |
| `apps/web` | 3040 | Next.js operator console |
| `apps/docs` | 3003 | Product documentation |

`GET /health` reports process liveness. `GET /ready` verifies the pinned
Memongo contract and a live transaction against the wiki store.
